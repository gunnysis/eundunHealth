# v0.4.0 Android release readiness

> 작성일: 2026-10-17
> 후보: Android `0.4.0` / `versionCode 37`
> 배포 전 상태: 태그·Play 업로드 전. 마지막 확인 Play production은 v0.3.1/36의 10% 단계 출시다.
> 배포 정책: 현재 운영자는 1명이므로 v0.4.0부터 production `completed`(100%)로 출시한다.

## 변경 범위

- Android 로그인 후 탐색을 `오늘·식단·진행·프로필` 적응형 메뉴트리로 이관한다.
- Health Connect 권한 상태·관리 진입·복귀 재조회를 보강한다.
- 백엔드 API, 컨테이너 이미지, 데이터베이스 migration, Azure 환경 변수는 변경하지 않는다. 따라서 이번 태그는 Android Play release만 트리거하며 Azure Container App revision을 새로 만들지 않는다.

## 태그 전 증거

- versionCode 단조성: 원장 `LAST_UPLOADED_VERSION_CODE=36`, 후보 37 (`scripts/bump-version.sh --dry-run 0.4.0` 통과).
- Android 품질: unit test, detekt, lintDebug, assembleDebug 통과.
- UI 품질: API 36 emulator에서 `connectedDebugAndroidTest` 통과. 네 최상위 목적지, Health Connect 사용 불가/연결 상태, Compose Accessibility Check를 포함한다.
- 문서: `doc_audit.py --collect-only`, `git diff --check` 통과.

## 배포·사후 검증 계약

1. `main`에 후보 커밋을 push한 뒤, 정확히 그 커밋에 `v0.4.0` annotated tag를 push한다.
2. `release.yml`이 CI의 Linux JDK에서 `preflight-release.sh`, 서명 AAB/APK, Sentry mapping, Play production `completed`(100%) upload를 수행한다. `userFraction`은 단계 출시 전용이므로 전달하지 않는다.
3. 성공 후 workflow가 Play upload ledger를 자동으로 `37`로 갱신한 커밋을 `main`에 push해야 한다.
4. 배포 완료 판단은 tag workflow 성공, Play track의 `completed` 상태, ledger commit을 함께 확인한 뒤에만 내린다. UI-only release이므로 Azure는 기존 revision의 health/readiness를 읽기 전용으로 확인한다.
5. 100% 출시는 되돌릴 수 없으므로 Crash/ANR·로그인·Health Connect 권한 흐름을 배포 직후 점검한다. 장애는 rollout halt 대신 더 높은 versionCode의 수정 릴리스로 교정한다.
